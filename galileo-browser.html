Desktop browser / in development

Galileo Browser is the first proof.

We took a Servo-derived shell and accelerated it toward a real desktop browser. The current build is useful for development and testing. There is no public release for everyday or security-sensitive browsing — and no page on this site will tell you otherwise.

The product boundary

A browser built around an engine, not a logo.

Servo — started by Mozilla Research in 2012 and carried forward by the open-source community and the Linux Foundation — supplies the web engine and a remarkable amount of standards work. We credit it in full, here and in the code. Galileo's browser engine layer connects that work to the desktop product: windows, tabs, navigation, profiles, settings, media, permissions, extensions, and release infrastructure.

Praising upstream is easiest when you are precise about what is ours. A working page is not a working browser; a working browser is not a secure release. Both gaps are on the roadmap.

Current work

The shell is becoming a product.

Repository evidence shows partial work across these surfaces. The status is deliberately conservative while focused qualification catches up.

01 / foundation

Pages, navigation, and browser state.

Rendering, URL and network work, tabs, browser chrome, profiles, private browsing, history, bookmarks, downloads, permissions, and session restore are active surfaces.

02 / hard cases

Media, blocking, and devtools.

GStreamer playback paths, Media Source Extensions work, native request blocking, privacy controls, WebDriver, and a developer-tools workbench are being qualified — including the official Cloudflare Turnstile canary, which passes in all three modes.

03 / extensions

Compatibility with a safety boundary.

Reviewed local packages, permission review, content CSS, browser-owned hosts, and MV2/MV3 entrypoints exist — without claiming broad Chrome or Firefox parity.

Extensions are part of the browser

Manifest V2, Chrome, Firefox, and Galileo.

We want the extensions people already rely on — especially ad blockers. When Manifest V3 made those extensions hard to ship, the biggest ad-blocker in the world left the biggest store. We are building the browser people should not have to leave to keep their tools: Manifest V2 support, a tested subset of Chrome and Firefox WebExtensions APIs, and a Galileo-native format for capabilities that should not be forced into someone else's model.

uBlock Origin is a named target. It is not a current compatibility claim — the official package earns the label only when its background page, content scripts, popup, storage, tabs, navigation, context menu, and blocking paths pass causal tests.

Privacy by architecture

Your browser, your data.

Most browsers make you an account so they can sync you to their cloud. Galileo is planned the other way around: local first, and synced to your devices — not to a company.

01 / local first

No account required to use a browser.

Profiles live on your machine. Local profile vaults add PIN or password protection around sensitive state — history, cookies, storage, downloads — with offline-first operation as the default.

02 / locked vaults

Locks you can hold.

Sensitive scopes deny access while a profile is locked, and export/import never carries the key material out. The vault contract is built and tested; production encryption of the profile data is next.

03 / sync without a landlord

Encrypted device-to-device sync.

Bookmarks, history, open tabs, and settings sync through encrypted envelopes designed for your LAN first — no cloud middleman, no account. The envelope format and conflict rules exist today; the transport is being built.

No public release

What “almost working” still leaves open.

We want a browser people can use and trust, so the missing work stays on the page.

Works in development

Builds open pages, expose browser chrome, exercise real-site and standards probes, run selected media paths, pass the Turnstile canary, and carry a growing set of browser-owned product services.

Still needs proof

Broad compatibility, process isolation, security response, startup speed, memory budgets, cross-platform packaging, signed updates, recovery, accessibility, and a supportable release channel.

A deliberate fork

Contribute back before we move away.

When Galileo's code is useful to the Servo engine and meets the project's contribution policy, we will offer it back for review — tested, and marked as AI-assisted where it is. If the maintainers decline, that is their right, and we will keep our boundary clear.

After the point where the engine names, product services, security decisions, and extension capabilities are fully ours, the browser engine completes its rename to Galileo and continues independently.
