Engine / lineage

From Servo to Galileo Browser.

GalileoEngine is an experimental browser engine derived from Servo. It preserves that technical foundation while developing the integration and browser-facing capabilities required by Galileo Browser.

One technical lineage

Three distinct responsibilities.

The relationship is deliberately simple: an upstream engine, a derived engine, and a product. Keeping those boundaries visible makes technical claims easier to understand and maintain.

  1. 01 / upstream

    Servo

    The Rust-based web engine and embedding foundation from which GalileoEngine is derived.

  2. 02 / derived engine

    GalileoEngine

    Maintains the derived engine, integration surface, focused compatibility work, and qualification method.

  3. 03 / browser product

    Galileo Browser

    The desktop experience that turns engine capability into a coherent product for people.

GalileoEngine is independent from Servo and is not affiliated with or endorsed by the Servo project.

What GalileoEngine adds

The work between engine code and a trusted browser.

01

Engine integration

Embedding, networking, storage, graphics, media, permissions, and browser-facing APIs must work together as one maintainable system.

02

Compatibility method

Standards tests, focused automation, and repeatable site journeys turn technical progress into evidence with documented limits.

03

Product readiness

Security, privacy, accessibility, stability, packaging, updates, and recovery require explicit gates before public release.

Upstream-minded

Stay derived without becoming disconnected.

Reusable engine improvements should remain useful to Servo whenever practical. GalileoEngine-specific decisions stay explicit and maintainable so the derived engine can continue to benefit from upstream progress.
