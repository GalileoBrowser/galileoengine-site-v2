The browser engine / the boundary

Keep the engine open. Change the pace.

Galileo begins where Servo ends: a browser engine in Rust, started by Mozilla Research in 2012 and carried forward by the open-source community and the Linux Foundation. We did not invent the foundation. We are changing its pace — and keeping the relationship honest for as long as the fork is close enough to give back.

A lineage worth naming

We did not invent the foundation.

What Mozilla Research and the maintainers who carried Servo forward built is a genuinely remarkable body of work: a Rust browser engine with a real rendering pipeline, serious standards implementation, and an architecture that invites extension. Galileo stands on all of it, and the code says so — the engine's internals still carry Servo's names on purpose, until the rename line is crossed.

Galileo's claim is narrower than "we built a browser": a small, focused team can use AI-assisted work to connect an existing engine to a much fuller browser surface in a short time. The speed belongs to our method. The foundation belongs to the people who built Servo.

Three layers

Different jobs. One honest boundary.

When these layers are confused, a fork starts making claims for code it does not own. Galileo names the handoff instead.

01 / upstream browser engine

Servo

The Rust browser engine: rendering, layout, web-platform implementation, and the embedding foundation we inherit and credit.

02 / accelerated fork

Galileo Engine

The accelerated browser engine: same foundation, plus the product integration, media, content blocking, extension runtime, and the tests around them — added since 26 July.

03 / user product

Galileo Browser

The desktop experience people will eventually use. It is not ready for everyday or security-sensitive browsing yet.

What the fork is doing now

Connect the hard parts.

These are real repository surfaces at the current head, not a promise that every surrounding workflow is release-ready.

01 / product shell

Make an engine feel like a browser.

Tabs, navigation, profiles, private browsing, settings, downloads, history, bookmarks, and recovery are being shaped into a desktop product.

02 / web reality

Make pages survive contact with the web.

Web Platform Tests, real-site journeys, media, WebDriver, storage, rendering, and compatibility probes — including the Cloudflare Turnstile canary — give us a way to see the gaps.

03 / trust surface

Put security before the launch button.

Content isolation, sandboxing, permissions, private data, updates, and crash recovery are release gates. Several remain unmeasured, and the page says which.

Upstream plan

Prove it here. Offer it back where it belongs.

We will try to send generally useful, tested fixes back to Servo — and we will mark them as AI-assisted where they are. Galileo will not treat that label as automatically acceptable: the code still has to be understood, tested, secure, and reviewed under Servo's own rules, and the maintainers accept what they want. If a fix does not fit Servo's scope or policy, the work stays public here and keeps serving the fork.
