Prefer the current-build helper

For macOS and Linux browsing work, the current README prefers the repo helper over a bare ./mach run. It builds and verifies the selected profile, preserves a backend-specific executable under target/stepper/run-builds/, and defaults to the medium profile with gstreamer. The Windows workflow remains the explicit mach build and mach run sequence shown above.

tools/run-current-build.sh youtube.com
tools/run-current-build.sh https://www.bbc.co.uk/
tools/run-current-build.sh --media-stack dummy https://example.com/

Testing

Useful local checks, plus the standard-library-only task runner with deterministic states, exit codes, timestamped logs, and JSON summaries. Compilation and browser profiles require an explicit --allow-costly flag.

./mach test-tidy
./mach test-unit
./mach build --production
./mach test-wpt dom
.venv/bin/python tools/stepper/stepper.py list
.venv/bin/python tools/stepper/stepper.py \
  run --profile static

Task contract, profiles, artifact schema and the Windows launcher: tools/stepper/README.md.

Reminder

These commands are copied from the current repository workflow. They launch the Stepper desktop shell through the inherited servoshell executable; a successful local build does not qualify packaging, installation, signing, updating, or production use — see Status.
