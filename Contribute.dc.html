Contribute

Make a change we can verify.

Volt needs focused changes with a clear owner, a reproducible baseline, and a testable exit gate. Small, reviewable work beats a large promise.

01 · Scope

Start from a bounded issue

Confirm the track, owner, baseline, and files in scope before implementation. Coordinate first if the work crosses another contributor's boundary.

02 · Evidence

Define the gate first

Record the current behavior, the expected result, and the exact command or test that proves the change. Unmeasured work remains unclaimed.

03 · Upstream

Keep engine work reusable

General Servo fixes should be written as upstream-quality changes. Volt-specific product work stays behind explicit shell and service boundaries.

Working agreement

A contribution is a measured handoff.

Keep the patch small enough to review, preserve unrelated work, and leave the next person with commands they can rerun.

  1. 01Read the roadmap and contribution contract before choosing a task.
  2. 02Capture a baseline and define the pass/fail evidence.
  3. 03Implement the smallest coherent change with regression coverage.
  4. 04Report commands, results, limitations, and ownership boundaries in the handoff.
Ready to begin?

Choose the smallest useful gate.
