How this snapshot is measured

The first graph point comes from Servo's successful public run at commit 93d8f85503e, the verified Galileo merge base. Galileo's first value is deliberately labelled as inherited: at that point the two projects share the same source revision, so the site does not pretend that a second browser run occurred.

The feature view counts all 68 rows in the reviewed Galileo feature inventory. The WPT view reports only the selected phase0-core shard. Galileo's retained report was produced at commit d0e89798d992; Servo's latest value was extracted from the public run at commit 386904a38308. Across both checkpoints, the three test identifiers and all 286 ordered subtest names match. Because the latest execution environments differ, that point remains an upstream reference rather than a controlled benchmark.

Future updates fail closed: when collection fails, the graph keeps the last verified point instead of drawing a guessed line. Each new point must name both commits and link to retained evidence.

Development path

Five stages from first build to public alpha.

We are working through the foundation now. Later stages begin only when the earlier work is stable enough to support them.

  1. 01Current

    Foundation & baseline

    Make builds repeatable and document the browser we inherited from Servo.

  2. 02Started

    Core browser journeys

    Test rendering, navigation, storage, media, and the desktop shell.

  3. 03Next

    Compatibility & hardening

    Expand standards, real-site, security, privacy, and accessibility work.

  4. 04Later

    Packaging & updates

    Build installation, updates, rollback, recovery, and platform integration.

  5. 05Goal

    Public alpha

    Release a clearly scoped first build after the required checks pass.

The highlighted step is where most of the work is happening now. Some tasks in the next step have already started.

The goal

A browser people can use and trust.

Opening pages is only the beginning. A real release also needs reliable standards support, user safety, accessibility, desktop stability, and a maintenance plan.

01

Web compatibility

Support modern standards and make more real websites work reliably.

02

Everyday browser features

Build the workflows people expect from a desktop browser.

03

Safe releases

Test security, privacy, accessibility, stability, installation, and updates.

04

A healthy Servo relationship

Keep useful engine work suitable for upstream whenever practical.
